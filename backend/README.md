# LifePilot AI — Backend

FastAPI + SQLAlchemy (async) + PostgreSQL + Redis/Celery backend for LifePilot AI.

The backend owns **app data** (budgets, expenses, meals, goals, schedule,
notifications, AI conversations). Better Auth owns normal app identities. The
backend verifies short-lived Better Auth JWTs through the issuer's JWKS and
keeps existing records keyed by the stable `payload_user_id` principal during
the staged identity migration.

## Quick start

From the repository root:

```bash
cp backend/.env.example backend/.env   # then configure BETTER_AUTH_URL
docker compose up -d postgres redis
docker compose up -d backend worker beat
```

- API: <http://localhost:8000/api/v1>
- OpenAPI docs: <http://localhost:8000/docs>
- Health: <http://localhost:8000/health>

`backend` runs `alembic upgrade head` before starting Uvicorn, so the schema is
created automatically. In `APP_ENV=development` the app also calls
`Base.metadata.create_all` as a convenience; production relies on Alembic only.

## Configuration

All settings are read from environment variables / `backend/.env` (see
`.env.example`).

| Variable | Purpose |
| --- | --- |
| `DATABASE_URL` | `postgresql+asyncpg://...` |
| `REDIS_URL` | Celery broker + result backend |
| `BETTER_AUTH_URL` | Public origin of the Better Auth issuer |
| `CORS_ORIGINS` | Comma-separated browser origins |
| `AI_PROVIDER` | `openai` or `anthropic` |
| `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` | Provider credentials (server-only) |
| `VAPID_PRIVATE_KEY` / `VAPID_PUBLIC_KEY` | Web Push keys |
| `SMTP_*` | Reminder email delivery |

AI endpoints return `503 ai_not_configured` when no provider key is present;
everything else works without one.

## Authentication

Send `Authorization: Bearer <better-auth-jwt>` with every request. FastAPI
fetches the issuer's JWKS and validates the RS256 signature, issuer, audience,
and expiration. The five-minute app token is derived from a valid Better Auth
session and is never stored in the browser.
`BETTER_AUTH_URL` is the public token issuer; set `BETTER_AUTH_JWKS_URL` to a
container-reachable URL when the backend cannot resolve that public origin.

`GET /api/v1/users/me` auto-creates the backend profile on first use.
`POST /api/v1/users/sync` refreshes it and rejects a body whose `auth_user_id`
differs from the verified token subject. Existing profiles can be linked by
setting `better_auth_user_id` while retaining their existing
`payload_user_id` ownership key.

## Frontend integration

The Next.js app in this repository talks to this API from the server only:

- `src/lib/lifepilot-api.ts` asks Better Auth for a short-lived server-side JWT
  and forwards it as `Authorization: Bearer …`. The token never reaches the
  browser.
- `BACKEND_URL` (server-only, default `http://127.0.0.1:8000`) points at this
  API. Set it in the Make environment when the backend is not on localhost.
- Server Actions in `src/app/(frontend)/app-actions.ts` wrap every mutation and
  return serialisable `{ ok, data } | { ok: false, error }` results; the client
  calls `router.refresh()` after a success.
- `src/lib/lifepilot-data.ts` loads the initial snapshot for the app shell.

Configure `BETTER_AUTH_URL` to the same public origin configured in the Next.js
app. The backend retrieves public signing keys from
`/auth/api/jwks`; it does not need the Better Auth secret or Payload's secret.

## API surface

| Area | Endpoints |
| --- | --- |
| Users | `GET/PATCH /users/me`, `POST /users/sync`, `GET/PATCH /users/me/notification-preferences` |
| Finance | budgets (+`/summary`, categories), expenses, recurring payments (+`/pay`) |
| Food | preferences, recipes, meal plans (+`/generate`, meal edit/move), grocery list |
| Goals | goals CRUD, `PATCH /goals/{id}/progress`, `PATCH /goals/{id}/financial` |
| Schedule | activities CRUD, `GET /free-slots`, `GET/PUT /working-hours`, AI proposals (+`/confirm`) |
| Notifications | inbox, `POST /{id}/read`, `POST /read-all`, push subscriptions, VAPID key |
| AI | conversations/messages, recommendations |

All user-owned rows remain scoped by the stable `payload_user_id` principal
during the transition, so linking an auth identity does not rewrite ownership.

## Migrations

```bash
docker compose run --rm backend alembic upgrade head
docker compose run --rm backend alembic downgrade base   # destructive
docker compose run --rm backend alembic check            # model/migration drift
```

The initial revision lives in `alembic/versions/`. Autogenerated revisions are
excluded from Ruff.

## Tests

```bash
docker compose exec -T backend pytest                  # unit tests (no server)
docker compose exec -T backend python scripts/smoke_test.py   # end-to-end
```

`scripts/smoke_test.py` still targets the legacy Payload JWT flow and must not be
used against this Better Auth setup until it is updated to obtain a test token
from a dedicated test issuer. It resets fixtures for its configured test user.

## Background jobs

Celery worker and beat run the reminder pipeline:

- `send_reminder` — in-app delivery, optional Web Push and email.
- `send_reminder_email` — SMTP delivery.
- `update_overdue_payments` — hourly beat task flagging overdue recurring payments.

Reminder rows are upserted per `(user, activity, type)`, so moving an activity
re-arms its existing reminders instead of duplicating them.
